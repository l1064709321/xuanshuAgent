# SK-001: 代码审查（Code Review）

## 触发条件
用户要求审查代码、检查质量、review PR、评估代码改动，或表达对代码质量的质疑。

## 审查维度

### 1. 安全审查（最高优先级）
逐行扫描：
- 注入风险：SQL拼接、Shell拼接（os.system/subprocess中字符串拼接）、HTML/JS内联注入、路径遍历（../未过滤）
- 凭据泄露：硬编码密钥/密码/Token、.env误提交、日志打印敏感信息
- 权限缺陷：缺少鉴权、默认开放而非默认关闭、用户输入直接作为文件路径

### 2. 逻辑与边界审查
- 空值/None/undefined是否每条路径都处理
- 循环退出条件是否可能永不满足
- 并发/竞态：共享变量是否有锁保护
- 递归是否有终止条件和最大深度

### 3. 性能审查
- O(n²)及以上是否可优化
- 循环内是否有不必要的I/O/网络请求/数据库查询
- 大文件是否流式处理而非全量加载内存

### 4. 可维护性审查
- 函数是否单一职责，超50行须解释
- 命名是否自解释
- 魔法数字是否提取为命名常量

### 5. 架构审查
- 模块耦合是否可解耦
- 是否存在循环导入
- 错误处理是否静默吞异常

## 分语言专项

### Python
- 裸except、可变默认参数、eval/exec/pickle非受信数据、文件未用with

### JavaScript
- innerHTML接收用户输入、eval/Function、Promise无catch、事件监听器未remove

### HTML/CSS
- XSS注入点（url()/onerror/javascript:协议）、viewport缺失、z-index堆叠失控

## 输出格式

按严重度分级输出报告：
- 🔴 阻塞：必须修复
- 🟡 建议：应修复但非阻塞
- 🟢 优化：锦上添花

每条问题附带：风险说明 + 修改建议 + 前后代码对比。

## 原则
- 一次审查≤500行，超出分段
- 不熟悉语言先声明边界
- 每条问题必须附带修改示例，不给方案等于没审查
