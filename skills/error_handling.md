# SK-004: 错误处理策略（Error Handling）

## 触发条件
设计错误处理逻辑、排查线上故障、评估系统健壮性。

## 错误分类矩阵
| 类型 | 可恢复性 | 策略 | 示例 |
|------|---------|------|------|
| 瞬态错误 | 是 | 重试 + 指数退避 | 网络超时、限流 |
| 配置错误 | 是 | 降级 + 告警 | 密钥过期、配额耗尽 |
| 数据错误 | 部分 | 跳过 + 记录 | 格式异常的单条数据 |
| 逻辑错误 | 否 | 熔断 + 回滚 | 状态不一致 |
| 资源错误 | 否 | 限流 + 扩容 | OOM、连接池耗尽 |

## 重试策略
```
重试: 最多 3 次，间隔 1s/2s/4s（指数退避）
熔断: 连续 5 次失败 → 熔断 30s → 半开探测
降级: 主路径失败 → 走缓存/默认值/静态兜底
```

## 错误信息规范
- 面向开发者：包含错误码、发生位置、上下文快照
- 面向用户：脱敏后的人类可读提示，不含堆栈
- 日志记录：完整错误栈 + 请求 ID + 时间戳

## 注意事项
- 不要吞掉异常（空 catch）
- 不要只打日志不处理
- 不要在循环里重试不检查退出条件
- 熔断恢复后要逐步放量，不要全量恢复

## 示例
```python
# ❌ 不好
except:
    pass

# ✅ 好
except ThirdPartyTimeout:
    retry_count += 1
    if retry_count > 3:
        raise CircuitBreakerOpen("third_party_api")
    time.sleep(2 ** retry_count)
    return self.call()
```
