# SK-002: 分层调试（Debugging）

## 触发条件
程序报错、异常行为、性能问题、结果不符合预期。

## 执行步骤
1. **日志优先**：先查已有日志/错误输出，不盲目改代码
2. **复现确认**：能否稳定复现？什么条件下触发？记录最小复现步骤
3. **二分定位**：对代码块二分注释/跳过，快速缩小嫌疑范围
4. **假设驱动**：提出"如果 X 是根因，应该观察到 Y"并验证
5. **隔离变量**：只改一处，验证后再改下一处；严禁一次改多处然后猜哪个生效
6. **根因修复**：修根因不要修症状；修完后写回归测试防止再次发生

## 工具选择决策树
```
有错误消息 → 读错误消息 + 查相关日志
  ├─ 网络/I/O → timeout/重试日志 + tcpdump/curl
  ├─ 数据库 → explain + slow query log
  ├─ 内存 → valgrind / memory profiler
  └─ 并发 → race detector / 加锁顺序检查
无错误消息 → 行为不符合预期
  ├─ 数据流问题 → print/log 关键变量
  ├─ 状态问题 → dump 状态快照
  └─ 时序问题 → 加 timestamp 日志
```

## 注意事项
- 不要跳过日志直接改代码
- 修复后运行回归测试确认没有引入新 bug
- 调试耗时超过 30 分钟仍无头绪，寻求结对或换个角度

## 示例
```
现象: API 返回 500，日志无异常
1. curl 直接请求 → 500
2. 在入口加 log → 请求确实到达
3. 二分注释中间件 → 第 3 个中间件触发
4. 加详细日志 → 发现是第 3 方 API 超时未捕获
修复: 加 try/except + 超时重试
```
